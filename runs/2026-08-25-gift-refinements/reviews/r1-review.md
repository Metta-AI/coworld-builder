### F1 — On an early (deadline) settle the `autobank` events land one tick past the last recorded frame

- **Where:** `src/gift_refinements/server.nim:386-423`; `src/gift_refinements/sim.nim:184-201`, `370-376`, `392-401`; `src/gift_refinements/replays.nim:217-225`.
- **Observed:** the round loop breaks at the top of an iteration (`server.nim:391-395`) with `sim.tick == (roundIndex-1) * ticksPerRound`, because `step()` increments `sim.tick` *after* `captureFrame()` (`sim.nim:395-401`). The settle then calls `sim.autobankAll()` (`server.nim:420`), and `bank()` stamps each row with `sim.tick` (`sim.nim:197`). So every settle `autobank` carries `t == lastFrameTick + 1`. `sim.finish()` correctly uses `max(0, sim.tick - 1)` for the `end` row and the `gameover` beat (`sim.nim:463-467`), which is why only the autobank rows are affected. The follow-up line `sim.frames[^1].tick = max(0, sim.tick - 1)` (`server.nim:421-422`) is a no-op: `captureFrame` already stamped that frame with exactly that tick.
- **Design note:** §End conditions (l. 259) — "rounds played are scored; every cog autobanks at the settling tick"; §The replay file (l. 666-675) — the replay is "self-sufficient by construction" and the viewer indexes "a tick → events map".
- **Consequence (inferred, untested):** `parseReplay` builds `byTick` from the row's `t` (`replays.nim:217-222`) and `maxTick()` is the last frame's tick (`replays.nim:227-228`), so those rows sit at an index the playhead can never reach: the closing cash-out draws no burst, no feed row, and `BroadcastTracker.resync(..., throughTick = maxTick)` (`broadcast.nim:74-82`) never folds them — the end-card's `TOKENS BANKED` total would then disagree with `results.scores`, which do include them (`sim.nim:191`). `tests/test_replay.nim:52-54` asserts `t >= 0 and t < played` for every event, which would catch this, but only plays `complete` episodes, so the deadline path is not covered by any test.
