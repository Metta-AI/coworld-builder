## New findings

1. **BLOCKING** — `prompts/60-verify.md:88-92` check 7 reads `/tmp/rr/release-result.json`, a file phase 40 downloaded into the sandbox's `/tmp` (`40-release.md:69-70`) in what is usually an earlier session; phase 40's Writes (`40-release.md:102-111`) persist only `version/cow_id/manifest_sha` and the policy labels, never `certify.replay_liveness` or the release run id in STATE, and `agents/verifier.md:78` forbids reusing "a fetch from an earlier phase or heartbeat". A verifier following the prompt finds no file → check 7 `NOT FETCHED` → false → 3 attempts → phase 90 on every run whose phase 60 starts in a new session. *Fix:* in `40-release.md` Writes, copy `release-result.json` to `runs/<run>/release-result.json` and record `coworld.release_run_id`; make check 7 read that path (or `gh run download "$(jq -r .coworld.release_run_id STATE.json)"`).

2. **BLOCKING** — `prompts/00-claim.md:77-83` (and `SPEC.md:41-42`) route a confidential top idea to `prompts/90-blocked.md` before a run task or STATE exists; 90 cannot run (`90-blocked.md:8-12,26-53` need `STATE.*` and "a subtask on the run task"), nothing marks the idea as skipped, and `00-claim.md:75-76` reselects it every hour — the queue is stuck behind one confidential idea forever, with an undefined 90 entered each firing. *Fix:* on a confidential idea, post one `skipped by coworld-builder: marked confidential` comment on the idea task, append the gid to a committed `runs/SKIPPED.json`, have step 4.2 skip gids in that file (and ideas carrying that comment), then continue to the next idea; never enter 90 without a run.

3. **BLOCKING** — `prompts/00-claim.md:107-118` (resume) has no race guard: two concurrent heartbeats that both observe `session_ended_at ≥ heartbeat_at` (or both observe a stale heartbeat) both write `heartbeat_at`, both push, and both work the phase; the rejected-push rule (`00-claim.md:104-106`) applies to claims only, and `deploy.py run` (`deploy.py:472-478`) makes concurrent firings routine. *Fix:* on resume, write a session nonce with the `heartbeat_at` (STATE `session_id` + the `00 resume … session=<nonce>` log line), `git pull --rebase` and push; if the push rejects, rebase and exit if `log.md`'s last `00 resume` line carries another nonce; then re-GET the Asana custom field after 20 s and exit if it moved past your stamp.

4. **MINOR** — `agents/judge.md:83-84` ("an unverifiable item is not automatically blocking") contradicts the judge brief at `prompts/30-review-loop.md:58` ("A checklist item you cannot verify counts as blocking"); `30-review-loop.md:10` says the checklist is the only source of "blocking". *Fix:* delete the sentence at `judge.md:83-84` and keep the brief's rule (or vice-versa), so the rule lives in one place.

5. **MINOR** — `templates/STATE.template.json` lacks `session_ended_at`, `policies.filler_version_ids`, `announce.attempted_at` (`SPEC.md:157,161,163`; written by `00-claim.md:101-102`, `50-league.md:123`, `70-announce.md:32`). *Fix:* add `"session_ended_at": null`, `"filler_version_ids": []`, `"attempted_at": null` to the template.

6. **MINOR** — `templates/run-task.md:3` (`$BUILDER_PROJECT`), `:14` (title `RUN <slug> — <idea title>` vs `00-claim.md:99`), `:50-70` and `templates/README.md:200-203` (heartbeat as a description line, "the task line is the lock") contradict `00-claim.md:21-35`/`AGENT.md:110-113` (custom field `1217748424048134`, `log.md` fallback). *Fix:* drop the description heartbeat line and its rules, say "heartbeat_at is custom field 1217748424048134", use the 00-claim title, replace `$BUILDER_PROJECT` with the gid reference.

7. **MINOR** — `templates/blocked-subtask.md:49-50` names `STATE.blocked` fields `what_failed, attempts, need, phase`; `90-blocked.md:28-32` writes `phase, at, ask, error, attempts, subtask`, and `00-claim.md:49` reads `subtask`. *Fix:* replace the template's field list with the six from `90-blocked.md`.

8. **MINOR** — `prompts/00-claim.md:95-96` tells a yielding heartbeat to append to `runs/<other-run>/log.md`, which `AGENT.md:173` (hard rule 7: "Do not touch another run's directory") forbids. *Fix:* write the yield only in the heartbeat's closing note (or a shared `runs/heartbeats.log`).

9. **MINOR** — every phase prompt depends on `jq` (`00-claim.md:25`, `20-build.md:81`, `40-release.md:60,70`, `50-league.md:33-110`, `60-verify.md:23-104`, `70-announce.md:24,43`), but the sandbox inventory the brief gives is git/gh/curl/python and no file asserts `jq` exists. *Fix:* add `command -v jq || exit` to 00-claim step 0 with a `python3 -c` fallback note, or verify once and record it in `fleet/cloud.md`.

10. **MINOR** — `prompts/80-close.md:47-49` says a phase-80 Asana failure "does **not** go to 90" and lets the next heartbeat retry, but the resume path `00-claim.md:107-111` increments `phase_attempts["80"]` on each retry and enters 90 at 3. *Fix:* exempt phase 80 from the resume counter (or state that three failed closes do go to 90).
