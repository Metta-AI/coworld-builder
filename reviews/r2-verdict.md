## New findings

1. **BLOCKING** — `prompts/00-claim.md:179-183` (and the same rule at `AGENT.md:26-28`, `docs/SPEC.md:39-40`): the resume race is adjudicated by "after `git pull --rebase`, exit if `log.md`'s *last* `00 resume` line carries a different nonce". A rebase replays the loser's commit on top of the winner's, so the loser's own line is last (or the two end-of-file appends conflict and the rebase halts, which no step handles) — the loser re-pushes and works the phase; the 20 s Asana re-GET at `:184-187` only catches the case where the winner stamps *after* the loser, which is not the case in which the loser's push was rejected. Two heartbeats (cron + `deploy.py run`) on the same free run both resume it — a duplicate run. *Fix (one line in each of the three files):* "after the rebase, exit if `log.md` now contains **any** `00 resume` line with a nonce other than yours that was not there before your pull (or if the rebase conflicts in `log.md`/`STATE.json` — `git rebase --abort` and exit)".

2. **BLOCKING** — `prompts/20-build.md:29` and `prompts/10-design.md:70` (and `playbooks/make-coworld.md:129`) specify the baseline switch as `PLAYER_SCRIPTED=1`, while `prompts/20-build.md:50`, `prompts/40-release.md:28,40-45`, `docs/SPEC.md:146`, `prompts/30-review-loop.md:125` and `templates/tools/ci/policies.json.example:21,28` specify `PLAYER_SCRIPTED=<baseline name>`. The builder brief contradicts itself 21 lines apart. A builder that implements the first statement (`== "1"`) ships a player that treats `PLAYER_SCRIPTED=basestock` as *not* scripted; both fillers then run the LLM path with no `PLAYER_PROMPT`, and done-items 4/5 (fallback counts, hosted-log `falling back` lines) fail in phase 60 — or, with a `!= ""` check, both fillers run the *same* baseline and the two distinct baselines the design note names are never fielded. *Fix:* replace `PLAYER_SCRIPTED=1` with `PLAYER_SCRIPTED=<baseline name>` at `20-build.md:29`, `10-design.md:70`, `make-coworld.md:129`.
